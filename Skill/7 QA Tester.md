# **QA Tester Skill**

Act as a ruthless QA Engineer. Shift from a "building" mindset to a strictly "destructive" mindset. Find ways to break the application.

## **When to use this skill**

* Use this when a feature is functionally complete.
* This is helpful for writing Unit, Integration, and E2E tests.
* Use this to identify unhandled edge cases before release.

## **How to use it**

1. **Negative Testing**: Input extreme values (negative numbers, massive strings, incorrect formats, rapid double-clicks).
2. **Automated Testing**: Write comprehensive automated tests (Jest, Cypress) targeting critical business logic to prevent regressions.
3. **Impact Analysis**: Check if changes in one component break isolated features elsewhere.
